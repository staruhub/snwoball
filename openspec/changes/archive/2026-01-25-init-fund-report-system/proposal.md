## Why

基金分析师和投资经理在日常工作中需要对基金产品进行多维度分析，但现有工具固化、无法灵活配置、需要手动整合多个数据源，效率低下。本提案旨在构建一个模块化、可拖拽的基金分析报告系统，让用户能够高效地创建、编辑和导出专业分析报告。

## What Changes

### 核心功能（P0 - MVP）

1. **用户认证** - 登录、注册、SSO 集成
2. **工作台首页** - 快捷入口、最近报告、收藏模板、市场速览
3. **报告管理中心** - 报告列表、筛选、排序、批量操作、回收站
4. **模板管理中心** - 系统模板、个人模板、模板预览
5. **报告编辑器**（核心）
   - 顶部操作栏：报告名称、全局筛选条件、保存状态
   - 左侧模块导航：树形结构、可折叠、支持搜索
   - 中间画布：模块卡片、拖拽排序、调整大小
   - 右侧配置面板：全局设置、模块参数配置
6. **模块操作** - 添加、删除、克隆、拖拽排序、调整大小
7. **参数配置** - 全局参数、模块参数、参数锁定机制
8. **全局样式设置** - 主题颜色、字体、样式模板
9. **PDF 导出** - 支持 A4 纵向/横向，可选封面、目录、页码

### 分析模块类型

- **产品信息**: 产品表头、基本信息、基金经理、费率信息等
- **基础分析**: 收益统计、风险统计、业绩表现、组合分析、净值归因
- **股票策略**: 风格分析、因子暴露、选股能力
- **债券策略**: 久期分析、信用分析、利率敏感性
- **FOF 分析**: 子基金配置、策略配置、风格穿透
- **风险监控**: 风险仪表盘、压力测试、情景分析
- **业绩比较**: 多基金对比、与基准对比、竞品分析

## Impact

### 新增能力

- `user-auth`: 用户认证与授权
- `workspace`: 工作台首页
- `report-management`: 报告管理中心
- `template-management`: 模板管理中心
- `report-editor`: 报告编辑器（核心）
- `pdf-export`: PDF 导出功能
- `user-settings`: 个人中心与偏好设置

### 技术影响

- 前端：需要实现完整的 Next.js App Router 应用架构
- 后端：需要实现 FastAPI RESTful API 服务
- 数据库：需要设计报告、模板、用户等核心数据模型
- 基础设施：需要配置 monorepo 开发环境

### 依赖条件

- 底层数据服务：各分析模块所需的基金数据 API
- 用户系统：用户登录态和权限验证
- 文件服务：PDF 生成和存储服务
